# DownstreamClient 生命周期命令收敛为意图接口

`DownstreamClient` 暴露的 `restart()` / `stop()` / `start()` 是物理动作命令，但实现的真实契约把错误重抛、请求合并、锁串行与停机标志时序藏在 seam 后面，调用者必须了解这些私有 flag 才能正确使用。我们决定把接口收敛为 `ensure_ready()` 与 `shutdown()` 两个意图：保持同步 fire-and-forget，失败在客户端内部自愈并只记日志，不再在下一次命令时向调用者重抛；`ensure_ready()` 统一走既有重启流程，不区分冷启动与重启。理由是该契约跨 seam 泄漏使领域无法预期同步重抛，而调用者实际只需两个意图；权威状态仍由领域聚合根的 `DownstreamLifecycle.transition` 单点改写，基础设施不持有也不改写它。

## Considered Options

- **改为异步并等待完成、返回显式结果**：被否决。会把领域三个调用点与命令/表现层签名全部改成 async，改动面大；物理层已自愈重试，调用者并不需要最终结果。
- **保留三个入口、仅改名加深实现**：被否决。调用者仍要区分三个物理动作，达不到「只学一个意图」的 Leverage 目标。
- **单一 `transition_to(state)` 入口**：被否决。与领域权威状态 seam 职责重叠，会让基础设施参与业务状态决策。
- **保持同步但返回「已接受」回执类型**：被否决。同步点拿不到最终结果，增加的类型不改变错误传达方式。

## Consequences

- `ensure_ready()` 返回时下游未必已就绪，调用方不得把返回当作就绪信号；就绪仍由领域权威状态与事件观测。
- 移除陈旧错误重抛；生命周期任务异常在任务完成回调中记录日志，不再传播到领域与命令处理器。
- 领域聚合根的重启、停机、唤醒三个调用点改为调用新意图接口，调用前后的权威状态迁移与原因不变。
- 既有测试对私有 flag 的白盒断言改为通过注入的进程管理器 spy 与事件观测 seam 不变量。
