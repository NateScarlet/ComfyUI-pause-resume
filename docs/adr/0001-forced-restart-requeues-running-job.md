# 强制重启下游时，正在执行的任务重新入列而非标记完成

当用户通过托盘强制重启下游时，正在执行的任务此前会被误判为「完成」并从队列中消失。我们决定：强制重启属于「中断」而非「完成」，被中断的 RUNNING 任务应重新入列（回到 PENDING）从头执行，与下游崩溃时的处理一致。强制重启不计入崩溃降级阈值，也不写入预估时长——该次执行没有产出，且不是任务本身的缺陷。

## Considered Options

- **标记为失败**：用户主动放弃该次执行，任务进入 `failed_workflows` 需手动重试。
- **阻塞重启**：执行中时「立即重启」改为等待当前任务完成再重启，改变两次点击的交互语义。

## Consequences

- 强制重启入口必须经由领域聚合根，不能由基础设施直接调用下游重启；否则领域无法感知中断，也就无法重入列。
- 「下游执行结束」从此有两种原因（完成 / 中断），领域必须区分，不能再把 `executing=False` 一律当作完成。
